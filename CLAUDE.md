# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`oas-rs` is a small typed HTTP framework on Hyper + Tokio that generates OpenAPI 3.1 at startup. Cargo workspace of two crates: `oas-rs` (root) and `oas-rs-macros` (proc-macro, `#[derive(ApiSchema)]`). MSRV is 1.88, edition 2024. The public API and HTTP semantics follow semver within the `0.7` line (see `CHANGELOG.md`).

## Commands

Run everything CI runs, in the pinned toolchain, before committing:

```bash
bash scripts/verify-docker.sh    # fmt, clippy (default + all features), tests, doctests, examples, rustdoc -D warnings
```

Without Docker, the same steps (feature flags matter — many tests/benches/examples declare `required-features`):

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-targets --features "uuid test-util swagger multipart tls http2 compression compression-brotli static-files websocket"
cargo test --doc --workspace
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --all-features
cargo test --features "uuid test-util swagger multipart tls http2 compression" percent_decode   # single test by name filter
cargo test --test derive                                         # single integration test file
cargo bench --bench router --features uuid,test-util,swagger     # microbenchmark (release profile)
cargo +nightly miri test --lib inline_future --                  # CI gate for the unsafe inline-future code
```

Cleanup step: after finishing a task or branch run `bash scripts/clean.sh`
(removes `target/` and the Docker cache volumes `oasrs-target` / `oasrs-cargo`, which can reach
12+ GB). Remove scratch crates, worktrees and temp logs created for experiments in the same step.

## Architecture

Two-phase lifecycle: `App` (mutable builder, `src/app.rs`) → `App::build()` → `AppRuntime` (immutable, `src/runtime.rs`) that serves requests. All route compilation, OpenAPI document and Swagger HTML are produced once at `build()`; request dispatch does no OpenAPI work.

- `src/lib.rs` is the crate root: it declares the modules and re-exports everything. Internal modules use `use crate::*;` (or `use super::*;`) so items are reachable as `crate::X`; new crate-internal helpers should be `pub(crate)` in their module. Only items re-exported from the root are public API.
- `src/router/` compiles routes into static lookup tables plus a dynamic trie. Path captures are never copied: they are packed byte ranges (`[u64; 8]` in `Params`, max 8 captures) into the request URI, decoded lazily by extractors. `NEEDS_PARAMS` / `NEEDS_CAPTURE` / `NEEDS_BODY` associated consts on handlers and extractors let the router skip work a handler doesn't use.
- `AppRuntime` wraps an `Arc<RuntimeInner>` (routes, state, middleware list). Middleware (`src/middleware.rs`, `src/trace.rs`, `src/bearer.rs`) is a chain of boxed futures ending in the `Host` terminal implemented by `RuntimeInner`: `Incoming` requests go to `ConnectionRuntime::prepare_direct`, in-memory requests (`oneshot`, tests, benches) to `RuntimeRef::handle`. `ConnectionRuntime::prepare` skips the chain entirely when no layers are registered, which keeps the zero-layer path allocation-identical to before; keep it that way and re-run the `middleware` benchmark cases after touching it.
- Scoped middleware: layers are stored as `ScopedLayer { scope, layer }` (`Scope::All | Prefix | Route`); `Next::run` skips layers whose scope misses the request and `RuntimeInner::has_matching_layer` lets requests no layer covers take the direct path. Scope matching must use `PathParts` (the router's splitter) so a scope is never narrower than routing, otherwise a scoped auth layer becomes a bypass; keep the multi-segment parity test (`a_scope_is_never_narrower_than_routing`) passing. `Group` (`src/group.rs`) forwards to `App`; every method returns `&mut Group`.
- `src/handler.rs` defines `Handler<S, Args>` (impls generated by `impl_extractor_handler!` for up to 8 extractors) and `RawHandler`. `InlineFuture` stores futures ≤ 64 bytes in a fixed buffer via `unsafe` instead of boxing; larger ones are `Box`ed. Changes here need `// SAFETY:` comments and must keep the Miri job green.
- `src/extract/` holds the `FromRequest` impls for `Path`, `Query`, `Header`, `Json`, `State`, `Option<T>`; each also reports its OpenAPI parameter/body metadata via `openapi_request()`. `src/response.rs` holds `IntoResponse` + `ResponseMetadata` (response type → HTTP response and OpenAPI schema), `ApiError` (problem-details JSON), and the response helpers.
- `src/schema.rs`: `ApiSchema` trait and built-in impls; `OpenApiQuery` is the derive-generated query-parameter/parse hook.
- Profiling note: under real TCP load the router/handler/response code is only about 2% of server CPU (about 75% is kernel syscalls, 8% Hyper), so socket-level settings (`accept_next` sets `TCP_NODELAY`) matter far more than router micro-optimizations; profile before optimizing.
- `src/codec.rs` / `src/path.rs`: percent-decoding, query parsing, route-template splitting and path normalization.
- `oas-rs-macros`: the derive generates `ApiSchema` + `OpenApiQuery` impls and a direct (non-serde) query parser when all field types are simple; otherwise it falls back to serde. Generated code refers to the runtime through `::oas_rs::__private` (`#[doc(hidden)]`), so anything the macro needs must be re-exported there. Serde `rename` / `rename_all` handling lives in `oas-rs-macros/src/serde_attrs.rs`; enums (unit-only as a string `enum`, otherwise `oneOf` for the four serde tagging forms) and the serde subset in `serde_attrs.rs` are supported; field-level `#[api_schema(..)]` and doc comments are read in `schema_attrs.rs`. The derive implements `schema_with(&mut SchemaRegistry)` through `registry.define::<Self>(name, ..)` (a `$ref` into `components.schemas`) and `schema()` as the same body on an inline registry; `App` owns the document registry and collects definitions at registration, so request/response metadata is built through the `*_with(registry)` methods (`openapi_request_with`, `response_schema_with`).
- Cargo features: `http2` (implies `tls`; after the TLS handshake `serve_tls` picks `hyper::server::conn::http2` when ALPN negotiated `h2`, otherwise HTTP/1.1; both are driven by the same watch/mpsc drain; no h2c on the plain listener; Hyper allows 200 concurrent streams per h2 connection (lower it with `http2_max_concurrent_streams`), so budget about 200 x `body_limit` of buffered bodies per h2 connection, and `header_read_timeout` does not apply to h2), `tls` (`serve_tls`; the accept loop is shared via `runtime::accept_next`, but the TLS path tracks connections with a `watch` shutdown signal plus an `mpsc` completion channel instead of `GracefulShutdown::watch`, because the handshake happens inside the per-connection task before a connection object exists), `multipart` (`Multipart`/`Field` extractor backed by `multer`; the body is buffered up to the route's limit, so memory per upload is about 3x `body_limit`), `swagger` (Swagger UI page, loaded from a pinned unpkg release with SRI hashes — update the hashes in `swagger_html` if the version changes), `websocket` (`WebSocketUpgrade` for raw routes over `tokio-tungstenite`; the HTTP/1.1 connections are then served `with_upgrades()`, and `runtime::drive` runs every connection (plain, h2c and TLS) with the shutdown signal because `GracefulShutdown::watch` cannot wrap an upgradeable connection), `static-files` (`ServeDir` middleware; adds `httpdate` and tokio `fs`), `compression` (`Compress` gzip middleware over `flate2`; compresses only buffered `ResponseBody::Full` bodies) and `compression-brotli` (adds `br` via the pure-Rust `brotli` crate; encoding choice is `negotiate` in `src/compress.rs`), `uuid`, `test-util` (exposes `TestResponse`/in-process dispatch used by tests and benches).

## Conventions specific to this repo

- HTTP semantics are specified in `README.md` (HEAD→GET fallback, automatic OPTIONS `204` + `Allow`, 404 vs 405, trailing-slash normalization, JSON media-type strictness, 1 MiB buffered body limit). Behavior changes need an acceptance test in `tests/acceptance.rs`.
- Releases go to crates.io: publish `oas-rs-macros` first, wait for the index to update, then `oas-rs` (its macros dependency is pinned `=version` with a `path` for local development).
- Performance work is judged against `benches/router.rs` (ns/op and allocations/op vs a raw-handler baseline); include before/after numbers. Design rationale is in `docs/benchmark-design.md`.
- Update `CHANGELOG.md` for user-visible changes. `python3` is not available on the dev machine (use `python`).
